## ลำดับสาธิต

1. เปิดเว็บออนไลน์และอธิบาย Vue → บริการหลัก/Gateway → Redirect service → PostgreSQL ร่วมกัน ตาม Architecture ทั้งสองบริการ Deploy แยกแล้ว
2. สมัคร Login สร้างลิงก์ คัดลอกเปิดปลายทาง สแกน QR มือถือและดาวน์โหลด PNG
3. รีเฟรชประวัติแสดงคลิกเพิ่ม อธิบายว่ารวมเปิดซ้ำ ไม่ใช่จำนวนคน
4. สลับสองบัญชีแสดงประวัติแยก Logout แล้วต้อง Login ใหม่
5. แสดง pagination ด้วยอย่างน้อย 11 รายการในบัญชีเดียว พร้อม ER/DFD และวิธีติดตั้ง
6. อธิบายข้อจำกัดและฟังก์ชันเสริมที่ทำจริง หลีกเลี่ยงแสดง Environment, cookie และรหัสผ่านระหว่างนำเสนอ

## ผลรอบฟังก์ชันใหม่ (ในเครื่อง)

Build ผ่าน ชุดทดสอบ PostgreSQL schema แยกครอบคลุม migration ซ้ำ รหัสซ้ำ/ผิดรูปแบบ วันหมดอายุ แก้ชื่อและสิทธิ์เจ้าของ ค้นหาข้ามหน้าแบบ literal และ HTTP 410 ไม่เพิ่มคลิก ตรวจ Browser จริง Desktop/Mobile: Login สร้างลิงก์ ค้นหา แก้ชื่อ Logout และหน้าหมดอายุ ไม่พบ horizontal overflow ผลนี้เป็นการทดสอบในเครื่อง ส่วนสถานะออนไลน์ล่าสุดอยู่ด้านล่าง

การลบ: ทดสอบสิทธิ์เจ้าของ/CSRF การลบซ้ำ การซ่อนประวัติและค้นหา แก้ชื่อหลังลบไม่ได้ GET/HEAD ตอบ 410 ไม่เพิ่มคลิก และ code ยังคงถูกจอง ไม่ได้ลบข้อมูลจริงออกจากฐานข้อมูล

ผู้ใช้ยืนยันว่าทดสอบฟังก์ชันชุดใหม่ในเครื่องผ่านแล้วในบทสนทนา หลังเพิ่มการลบพบ Backend พอร์ต 3059 ยังเป็นโค้ดเก่า จึงรีสตาร์ตและตรวจ API จริง: สร้างลิงก์ → ลบตอบ 204 → เปิดลิงก์เดิมตอบ 410 ผ่าน ผลทดสอบนี้ไม่ใช่การยืนยันบน Render

## ผลรอบ Microservices

รายละเอียดการตรวจโค้ด เอกสาร และข้อจำกัดก่อน Commit อยู่ใน [REVIEW.md](REVIEW.md)

ตรวจซ้ำวันที่ 16 ตุลาคม 2026: `npm.cmd test --prefix server` ผ่าน 4/4 ชุด (local rollback, two services, gateway failure/configuration และการป้องกัน .env เปลี่ยนฐานข้อมูลของ local launcher), `npm.cmd run build --prefix client` ผ่าน และแผนภาพ Mermaid ปัจจุบันทั้ง 5 ภาพเรนเดอร์ผ่าน ตรวจ Browser จริงซ้ำทั้ง Desktop/Mobile รวมบริการ Redirect ล่มแล้วหน้าจัดการยังทำงาน ผ่าน

ทดสอบ PostgreSQL schema แยกทั้ง local rollback และสอง process จริง ครอบคลุมสมาชิก/เจ้าของ/รหัส/หมดอายุ/ลบ/GET/HEAD ผ่าน พร้อมทดสอบ gateway ไม่ส่ง cookie, ไม่ตาม Location, token ผิด, upstream ล่ม, timeout และไม่ retry อัตโนมัติ ตรวจ Browser Desktop/Mobile กับสองบริการจริงผ่าน รวมตอนหยุด Redirect แล้วหน้าหลักยังใช้งานได้ หน้า 503 มีปุ่มลองใหม่ ไม่มีเนื้อหาล้นแนวนอน Build และแผนภาพ Mermaid ทั้ง 5 ภาพผ่าน ไม่มี migration ใหม่ ผลนี้ไม่ใช่ผลออนไลน์ อ่านขั้นตอนตรวจรับออนไลน์ใน [MICROSERVICES.md](MICROSERVICES.md)

### ประวัติเหตุการณ์ 503 ก่อนเปิดโหมด browser

หลักฐานเพิ่มเติมจากผู้ใช้หลัง PR #10: Gateway บันทึก `attempts=67, elapsedMs=70001, last=http-502` จากนั้นเปิด health ของ Redirect ตรงใน Browser พบหน้า Render `SERVICE WAKING UP` ก่อนแสดง JSON ok และผู้ใช้ยืนยันลิงก์กลับมาเปิดได้ การเปิดครั้งแรกหลัง idle จึงยังไม่ผ่าน ไม่มีหลักฐานว่าการเพิ่มเวลารอหรือ retry health เพียงอย่างเดียวแก้อาการครบ

จึงพัฒนาโหมด browser handoff และทดสอบในเครื่อง 5/5 กับ Browser ผ่าน ต่อมา Merge/Deploy และเปิดใช้งานแล้วตาม [ผลออนไลน์ล่าสุด](#ผลออนไลน์ล่าสุดในโหมด-browser) เก็บเหตุการณ์ 503 ช่วง proxy เป็นประวัติ ไม่อ้างว่าโหมดใหม่จะไม่มีปัญหาโฮสต์อีกแน่นอน

ผลติดตามหลัง Deploy การรอ health รอบแรก: ผู้ใช้ยังพบอาการหลังพัก พร้อม Logs บริการหลัก `Redirect request failed: readiness timeout` จึงยังไม่ผ่านการทดสอบหลัง idle ผู้ช่วยตรวจ read-only รอบถัดมาพบ health ตอบ 200 หลังประมาณ 23 วินาที และ HEAD ของ SekLoso ตอบ 302 หลังประมาณ 24 วินาที ยืนยันว่าบริการกลับมาทำงานได้ แต่ยังไม่มี Logs ของ Redirect ที่ระบุสาเหตุขณะเสีย

การแก้ fix/redirect-readiness-timeout เพิ่ม timeout 5 วินาทีต่อ health probe รวม body พร้อม Logs ทดสอบในเครื่องผ่าน 4/4 และ Merge/Deploy แล้ว แต่ยังพบ http-502 จนครบเวลารอบนอก จึงไม่ถือว่าการแก้ proxy รอบนั้นทำให้ idle ผ่าน

การแก้ fix/redirect-cold-start รอบแรกเพิ่มการรอ health ก่อนเปิดลิงก์ ทดสอบในเครื่องผ่าน 4/4 และ Merge/Deploy แล้ว แต่ยังเกิด readiness timeout ผลในเครื่องจึงไม่ใช่หลักฐานว่าออนไลน์ผ่าน ต่อมาจึงเพิ่มข้อมูลวิเคราะห์และเปลี่ยนเส้นทางเป็น browser

ผู้ใช้พบหลายลิงก์แสดงหน้า 503 และคลิกไม่เพิ่มในช่วงที่เปิดไม่ได้ ต่อมากลับมา Redirect และแสดงหน้าหมดอายุ 410 ได้ ผู้ช่วยตรวจแบบไม่เพิ่มคลิกพบ `/healthz` ของ Redirect ตอบ 200 หลังรอประมาณ 22 วินาที, `/api/health` บริการหลักตอบ 200 และ HEAD `/r/Test1` ตอบ 302 ไป example.com ประมาณ 223 ms

อาการสอดคล้องกับการเริ่มบริการหลังพัก แต่ไม่มี Logs ที่ยืนยันสาเหตุ จึงไม่สรุปว่าเกิดจาก cold start แน่นอน และไม่ถือว่าทดสอบความเสถียรครบแล้ว หากเกิดซ้ำให้เก็บเวลาที่เกิดและ Logs ของทั้งสองบริการ ไม่จงใจหยุดบริการจริงในรอบอัปเดตเอกสาร

ผู้ใช้เคยพบปุ่มสร้างลิงก์หมุนนานด้วย ยังไม่มี Logs ระบุว่ารอ POST สร้างหรือโหลดประวัติหลังสร้าง และ Frontend ยังไม่มี timeout ของ API ทั่วไป จึงคงเป็นอาการที่ต้องตรวจหากเกิดซ้ำ ไม่ถือว่าแก้แล้วจากการกลับมาเปิดลิงก์ได้

การค้นหาปัจจุบันเป็นการจับคำที่อยู่ในชื่อ URL ต้นฉบับ หรือ code ก่อนแบ่งหน้า ไม่แยกตัวพิมพ์เล็ก/ใหญ่ แต่ไม่ตัดช่องว่างกลางคำ ผู้ใช้ยืนยันค้น `ทดสอบ 2` พบรายการที่อยู่หน้า 2 และรับทราบว่าค้น `1` จะพบ URL ที่มี `start_radio=1` ด้วย การแก้ให้ไม่สนช่องว่างถูกย้อนกลับตามคำขอแล้ว ไม่อ้างว่าเวอร์ชันนี้รองรับการค้นแบบนั้น
